**Substitution note:** The 1TB logs were infeasible on our hardware, so we used the smaller Display Advertising Challenge set instead. Even that was too slow for a full scaling sweep with repeats: one 16-core run on all 45.8M rows took 22.6 min. The sweep therefore uses a deterministic subset of 1,000,612 rows (2.2%), selected by hashing the stable row id (`scripts/01b_make_subset.py`), so every run sees exactly the same rows.

## 2. Description
Each row is one ad impression: `label` (clicked = 1), 13 integer features (`I1-I13`, counts/numerics) and 26 categorical features (`C1-C26`, hashed to 32-bit hex strings). Feature names and meanings are deliberately undisclosed by the publisher. In `dac-v1` the click rate is 25.7% (measured on our subset), because Criteo sub-sampled clicked and non-clicked examples at different rates when building the dataset; real-world click rates are much lower. Missing values are common: `I1` is missing in 45.3% of rows. The training file covers 7 days of traffic and is chronologically ordered.

## 3. Collection and personal data
- Published by the data owner as an anonymised research dataset. All categorical values are hashed; no names, emails, IPs or free text.
- **We made no attempt to re-identify individuals, devices or advertisers**, and the code contains no such step.
- Even anonymised behavioural logs are treated as sensitive: they are not redistributed in this repo (`data/` is git-ignored); only download instructions are given.

## 4. Preprocessing (this repo)
1. TSV -> Parquet (`scripts/01_prepare_data.py`), adds stable row id `rid`; deterministic row subset (`scripts/01b_make_subset.py`).
2. Missing ints -> 0, then `log1p`. Missing categoricals -> `__missing__`.
3. Categoricals hashed into `2^hash_bits` buckets (FeatureHasher). Collisions are expected and traded off against memory.
4. Deterministic 80/20 train/test split by hash of `rid` (no temporal split, see limitations).

## 5. Known limitations and risks
- Features are anonymised, so we **cannot audit fairness by real-world groups**; the only slice we check is the data-quality slice "I1 missing vs present".
- Random (not time-based) split can overstate real-world accuracy for ads; a temporal split is the production-realistic choice.
- Results on a 2.2% sub-sample of the small Criteo set may not extrapolate to the full set or to the 1TB logs.
- The 25.7% click rate reflects Criteo's sub-sampling, not real traffic, so predicted probabilities are not calibrated to real click rates.
- Synthetic data has weak signal (AUC near 0.5) by design; it validates code paths only.
